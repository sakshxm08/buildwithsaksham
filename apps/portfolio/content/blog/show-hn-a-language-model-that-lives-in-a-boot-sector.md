## Show HN: A language model that lives in a boot sector  

If you’ve ever wondered how small a neural network can get, the **bootgpt** project on GitHub provides a concrete answer. The repository (kerlenton/bootgpt) ships a complete boot‑sector implementation that loads a tiny int8 model and runs it entirely in 16‑bit real mode on a 386‑class CPU—no operating system, no C runtime, just raw assembly.

### The architecture in a nutshell  

The Master Boot Record (MBR) is a 512‑byte hand‑written assembly stub (`boot.asm`). Its only job is to invoke BIOS interrupt 13h to read the next 23 sectors from the disk, which contain an 11.5 KB neural network. The model itself is a character‑level network with **8 characters of context** and a **single hidden layer**. All weights are quantized to int8 with power‑of‑two scales, allowing the forward pass to be expressed with a handful of `imul` instructions and a single `idiv`.  

Because the model runs in 16‑bit mode, the code cannot rely on any modern CPU features. Instead, it uses the integer arithmetic that the original 386 provided. The Python training script (`train.py`) mirrors this exact arithmetic, including the linear‑congruential generator (LCG) used for sampling, so the output of the Python model and the boot‑sector model match character for character.

### What the model actually does  

When the boot sector finishes loading, it “dreams” a Linux boot log. The generated text looks like a typical dmesg output, complete with timestamps, PCI BAR listings, ACPI events, and even a fake kernel command line. An excerpt from the demo reads:

```
[ 2.283888] pci 0000:01:01.4: [1b36:0a35] ryndrde c4128 6422 Vveine
[ 1.953886] pci 0000:01:1f.2: reg 0x10: [mem 0x7e4515e5-0x2d766c27] usbbore: reg
[ 0.206596] Command line: BOOT_IMAGE=/vmlinu -5.5.2-1-generic gcc version 13.3.0, GNU ld ...
[ 1.815765] ACPI: PCI Interrupt Link [LNKA: v/s.xos212
[ 1.883084] NET: Registered protocol family 16
```

The output is deterministic for a given seed because the training data consists of **3 MB of synthetic dmesg** generated by `corpus_gen.py`. The script creates one kernel version and one disk layout per boot session, ensuring that the model sees enough repetition to appear coherent despite its tiny size.

### Building and running  

The repository provides a straightforward build pipeline:

```bash
brew install nasm qemu
python3 -m venv .venv && .venv/bin/pip install numpy
./build.sh
./run.sh
```

`build.sh` assembles `boot.asm`, compiles the model, and writes everything into a `disk.img` file. The image can be written to a USB stick with `dd` and booted on any BIOS‑based machine. The boot sector only reads the sectors it owns, so it works on a bare metal box without any external dependencies.

### Why this matters  

Bootgpt demonstrates that a neural network can be embedded in the most constrained execution environment we normally associate with firmware. The project touches several niche but interesting topics:

- **Size‑coding**: fitting a functional model into 11.5 KB of raw bytes.
- **Demoscene**: the entire runtime lives in the MBR, a classic playground for low‑level tricks.
- **Machine‑learning on legacy hardware**: the forward pass runs on a 386 CPU without any SIMD extensions.

The approach also highlights the trade‑offs of extreme quantization. By restricting weights to int8 and using power‑of‑two scales, the model avoids floating‑point operations entirely, but it also limits the expressive power to what can be captured with a single hidden layer and a tiny context window.

### Limitations and future directions  

Because the model is trained on synthetic data, its output is intentionally nonsensical beyond the surface‑level boot‑log format. The repository notes that real boot logs repeat themselves, and that repetition is what makes a tiny model “look sane.” Scaling the approach to more meaningful tasks would require either larger context windows, deeper architectures, or smarter data generation—each of which would quickly exceed the 512‑byte boot‑sector budget.

Nevertheless, the project serves as a proof‑of‑concept for ultra‑compact inference. It could inspire experiments such as:

- Embedding tiny classifiers in firmware for early‑stage hardware diagnostics.
- Using similar techniques to verify boot integrity by generating cryptographic challenges on the fly.
- Exploring other domains where a fixed, tiny vocabulary and deterministic output are acceptable.

### Getting involved  

The GitHub repo is open‑source under the MIT license. It currently has **26 stars** and no forks, indicating a niche but interested audience. Contributions could focus on:

- Adding support for other architectures (e.g., UEFI).
- Experimenting with different quantization schemes.
- Extending the training pipeline to use real boot logs while still respecting the size constraints.

If you’re curious, the demo GIF (`bootgpt_demo.gif`) and MP4 (`bootgpt_demo.mp4`) in the repository showcase the model’s output in a QEMU window, giving a quick visual sense of what the boot sector produces.
