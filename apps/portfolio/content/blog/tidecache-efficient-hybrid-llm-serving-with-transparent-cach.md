Hybrid language‑model architectures are now the norm for open‑weight LLMs, mixing a few global‑attention layers with bounded‑state layers such as sliding‑window or recurrent modules. That mix creates several heterogeneous caches—global‑attention KV, window caches, recurrent states—each with different memory footprints and latency characteristics. The new paper *TideCache: Efficient Hybrid LLM Serving with Transparent Cache Management and Layer‑Wise Streaming* (arXiv 2611.26619, 19 Nov 2026) tackles this mismatch on CPU‑GPU superchips, where high‑bandwidth interconnects (up to 1.8 TB/s on Vera Rubin) make host memory a viable second tier for cache residency.

The post walks through TideCache’s three core components: the Transparent Cache Pool that reshuffles physical pages behind fixed virtual addresses, the Cache Streamer that prefetches the next global‑attention prefix during bounded‑state computation, and the Request Scheduler that picks resident or streamed execution based on request size and queue state. We’ll see how these ideas let the system release HBM for other caches, delivering up to a 2.04× increase in agent turns, 20–59 % lower P50 per‑token latency, and 1.40–3.05× faster first‑token times compared with the prior SGLang + HiCache baseline.

## what happened

TideCache was unveiled as a serving system built for hybrid large‑language models that run on CPU‑GPU superchips.  The design groups three cooperating components: a **Transparent Cache Pool** that shuffles physical GPU pages among the heterogeneous caches (global‑attention KV, sliding‑window caches, and recurrent states) while keeping each cache’s virtual address space unchanged; a **Cache Streamer** that leverages the idle decode interval of bounded‑state layers to pre‑fetch the next global‑attention prefix into shared GPU slots, thereby shrinking the amount of GPU‑resident data; and a **Request Scheduler** that decides, per incoming request, whether to run a resident or streamed execution and triggers capacity adjustments based on request size and queue pressure.

A key technical move is the dynamic reallocation of HBM across these cache components.  By decoupling physical page placement from the logical layout, TideCache can release memory freed by streaming a global‑attention prefix and immediately hand it to other caches or to newly arriving requests, all without breaking the existing backend interfaces.  The virtual addresses remain stable, so the rest of the serving stack sees a consistent cache layout even as the underlying pages move between GPU and host memory.

The authors implemented the whole stack inside **SGLang**, a language for describing LLM serving pipelines.  Evaluation was carried out on two NVIDIA superchips—**Grace‑Basilisk GB300** and **Grace‑Hopper GH200**—covering seven distinct model‑platform pairings that span a range of hybrid architectures (e.g., models mixing full‑attention layers with sliding‑window or recurrent layers).  Across these configurations, TideCache achieved up to **2.04 ×** higher throughput measured in agent turns, cut the 50th‑percentile per‑token latency by **20 %–59 %**, and accelerated first‑token generation (TTFT) by **1.40 ×–3.05 ×** compared with the baseline SGLang + HiCache setup.

## why it matters

Hybrid LLMs stitch together a few global‑attention layers with many bounded‑state layers (sliding‑window, recurrent, or Mamba‑style). The global‑attention KV cache grows linearly with the prompt length, while each bounded‑state layer only needs a fixed‑size state per token. When a service receives a mix of long‑context chats, multi‑turn coding sessions, and document‑analysis queries, the relative pressure on these caches shifts dramatically. A single request that reuses a long context can monopolise the global‑attention cache, whereas a burst of short, concurrent requests can saturate the bounded‑state caches. Because the caches sit in GPU HBM, this variability directly caps the number of requests a GPU can handle at any moment, forcing operators to over‑provision hardware or accept higher latency.

CPU‑GPU superchips change the equation by exposing a high‑bandwidth link between GPU memory and host DRAM. Grace Hopper’s NVLink‑C2C delivers about 900 GB/s, and the upcoming Vera Rubin chip pushes that to roughly 1.8 TB/s—an order‑of‑magnitude jump from the 64 GB/s PCIe 4.0 bandwidth on older A100 GPUs. This bandwidth makes it practical to keep portions of the KV cache in host memory and pull them into HBM just in time, effectively adding a second cache tier without sacrificing throughput.

TideCache leverages that tiered hierarchy. By streaming the prefix of the next global‑attention layer into shared GPU slots while the current bounded‑state layer is still computing, it overlaps data movement with useful work. The Transparent Cache Pool then reshuffles physical pages across cache components, freeing HBM for other active requests. In practice the paper reports up to a 2.04× increase in completed agent turns and a 20–59 % reduction in P50 per‑token latency compared with a baseline that keeps all caches resident.

For real‑world workloads—interactive chat, tool‑augmented coding agents, or document‑analysis pipelines—those gains translate into higher QPS, lower tail latency, and better utilisation of expensive GPU resources. The ability to share GPU memory across heterogeneous caches and to hide transfer costs behind computation means we can serve more users with the same hardware footprint, a crucial advantage as hybrid models become the default for production LLM services.

## how it works (background)

Hybrid language models interleave two very different kinds of layers. The global‑attention layers are the classic full‑self‑attention blocks that need to keep a key‑value (KV) cache whose size grows linearly with the total context length. In contrast, the bounded‑state layers—such as sliding‑window attention, Mamba, Gated DeltaNet and similar recurrent‑style modules—maintain a cache whose memory per request is fixed regardless of how many tokens have been processed. Because the bounded‑state cache does not expand with context, it can be kept resident in GPU memory even when many long‑running requests share the same device.

The Transparent Cache Pool (TCP) sits between the model’s logical cache layout and the physical GPU memory. It maps a set of fixed virtual addresses, which the existing inference back‑ends already use, onto a pool of physical GPU pages that can be re‑allocated on the fly. When a global‑attention layer finishes, its KV pages can be swapped out to host memory while the TCP silently hands those pages to another cache component, all without changing the model’s view of its own cache. This indirection preserves the original backend interfaces and lets the system treat the GPU memory as a shared, dynamically partitioned resource.

The Cache Streamer exploits the idle compute windows that bounded‑state layers naturally create. Those layers finish their computation before the next global‑attention block begins, giving a deterministic interval during which the system can prefetch the prefix of the upcoming global‑attention KV into a set of shared GPU slots. By overlapping this transfer with the decoding work of the bounded‑state layer, the streamer reduces the time the global‑attention cache needs to stay resident, while the generated KV for already‑processed tokens remains on‑device.

Finally, the Request Scheduler decides, for each incoming request, whether to run it entirely resident (if enough GPU cache is available) or to use streamed execution (if the request is large or the queue is busy). It monitors request size and the current queue state, then adjusts the capacities allocated to each cache component in the TCP. This dynamic balancing lets the system accommodate more concurrent requests, freeing HBM for other cache components and improving overall throughput.

## the key details and numbers

TideCache’s most striking headline is the throughput boost it delivers for agent‑driven workloads. When we replace the baseline SGLang stack that uses HiCache with TideCache, the system completes up to **2.04 × more agent turns** across the seven model/platform configurations we evaluated on GB300 and GH200. This gain comes from the combination of a transparent cache pool that reshuffles physical pages on‑the‑fly and a cache streamer that overlaps layer‑wise transfers with computation, keeping more of the GPU’s high‑bandwidth memory (HBM) available for active work.

Latency also improves dramatically. Across all tested settings, the **median (P50) per‑token latency drops by 20 % to 59 %** compared with the HiCache baseline. The reduction is not uniform because different hybrid models have varying proportions of global‑attention and bounded‑state layers; nevertheless, every configuration shows a noticeable shift of the latency distribution toward the left, meaning that most tokens are processed faster without sacrificing accuracy.

For interactive agents, the time‑to‑first‑token (TTFT) is a critical user‑experience metric. TideCache shortens the **agent P50 TTFT by a factor of 1.40 × to 3.05 ×** relative to the baseline. The improvement stems from the cache streamer’s ability to pre‑fetch the next global‑attention prefix during the idle decode intervals of bounded‑state layers, so the first token of a new request can be emitted as soon as the computation window opens.

Because the streamer frees GPU pages that would otherwise be tied up by global‑attention KV caches, that memory is immediately reclaimed by the transparent cache pool. The reclaimed HBM is then re‑allocated to other cache components—such as window caches or recurrent states—and can also accommodate additional incoming requests that arrive while the system is already busy. In practice, this dynamic sharing lets the GPU sustain higher concurrency without needing extra hardware, turning otherwise idle memory bandwidth into a tangible capacity gain.

## what it means for developers

What it means for developers is that a hybrid LLM can now run on a single GPU without the throughput penalty that traditionally forced us to split a model across multiple devices. TideCache’s Transparent Cache Pool lets the various cache components—global‑attention KV, window caches, and bounded‑state states—share physical GPU pages while keeping their virtual addresses unchanged. Because the layout that the model expects never moves, you can drop the whole system into an existing SGLang service with just a few API calls; there is no need to re‑architect the model or to rewrite the memory‑management code that the framework already provides.

The integration surface is deliberately thin. TideCache is implemented as a library on top of SGLang, so you only need to enable the cache‑streaming mode and point the scheduler at the new request‑queue logic. All of the heavy lifting—page redistribution, prefetching, and residency decisions—is handled inside the library. From a developer’s perspective the change is comparable to swapping in a different optimizer: the model code, its forward‑pass signatures, and the virtual‑address expectations remain exactly the same.

Beyond the memory savings, TideCache exploits the idle bandwidth that appears between bounded‑state layer computation and the next global‑attention layer. The Cache Streamer overlaps the transfer of the next layer’s prefix with the current layer’s decode, turning what used to be a quiet period on the CPU‑GPU interconnect into useful work. In practice the authors report a 20‑59 % reduction in P50 per‑token latency and up to a 2.04× increase in the number of agent turns completed on the same hardware.

For interactive agents and multi‑turn applications this translates into noticeably snappier user experiences. Lower per‑token latency means faster turn‑around for chat‑style bots, while the higher throughput lets you serve more concurrent sessions on the same GPU. In short, developers get the benefits of hybrid architectures—richer attention patterns and longer context windows—without the usual hardware cost or invasive code changes.

## limits and caveats

TideCache’s gains lean heavily on the bandwidth of the CPU‑GPU link. The paper notes that modern superchips such as Grace Hopper achieve up to 1.8 TB/s over NVLink‑C2C, an order of magnitude higher than the 64 GB/s PCIe 4.0 link on older A100‑class GPUs. When the interconnect is slower, the overlap between layer‑wise transfers and computation shrinks, and the benefit of streaming cache pages can disappear. In practice, deployments on machines with PCIe 3.0 or early PCIe 4.0 may see only modest latency reductions, or even a net slowdown if the transfer overhead dominates the compute savings.

The streaming mechanism also assumes that bounded‑state layers expose regular, predictable computation intervals that the Cache Streamer can use for prefetching. TideCache’s design relies on these intervals to pull the next global‑attention prefix into GPU memory just in time. If a model’s recurrent or sliding‑window layers have irregular timing—due to dynamic token lengths, variable‑length prompts, or adaptive routing—the prefetch window can be missed, forcing the system to fall back to resident execution. This reduces the effective overlap and can increase per‑token latency, especially for workloads with highly variable request patterns.

Finally, the evaluation covers only seven model/platform configurations on two hardware families (GB300 and GH200). While the results show up to 2.04 × more agent turns and 20–59 % latency reductions, they do not prove that the same techniques will transfer to other superchips (e.g., future NVIDIA Hopper successors or AMD CDNA‑based systems) or to model families with different cache hierarchies. Without broader benchmarks, we cannot be certain that the Transparent Cache Pool and Cache Streamer will behave similarly on, say, a model that mixes dense attention with more exotic sparse kernels, or on a platform where host‑to‑device bandwidth scales differently. Users should therefore treat the reported improvements as a promising baseline rather than a guaranteed outcome for all hybrid LLM deployments.

## Key takeaways

- TideCache introduces a Transparent Cache Pool that dynamically reallocates physical GPU pages among heterogeneous cache components while keeping their virtual addresses unchanged.  
- Its Cache Streamer pre‑fetches the next global‑attention layer’s prefix during the computation interval of bounded‑state layers, overlapping data transfer with execution and reducing GPU residency for global‑attention caches.  
- The Request Scheduler decides between resident and streamed execution per request and adjusts cache capacities based on request size and queue state, allowing freed HBM to serve additional cache components or new requests.  
- In experiments on NVIDIA GB300 and GH200 superchips across seven model/platform configurations, TideCache processes up to **2.04×** more agent turns than the baseline SGLang with HiCache.  
- The system cuts overall P50 per‑token latency by **20 %–59 %** and speeds up agent P50 time‑to‑first‑token (TTFT) by **1.40×–3.05×** compared with the same baseline.
